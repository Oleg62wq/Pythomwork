# DWA (статичная цель + HOLD) на распе, `u_prev` из энкодеров STM

Новый алгоритм `DWA_HumanFollower_v3_StaticTarget_Stop.m`, переведённый на C с
OpenMP, как были v2/v3. Плюс блок в прошивке STM, который считает реальную скорость
корпуса по колёсам и отдаёт её в DWA вместо предыдущей команды.

## Весь стек (что где лежит)

```
                       Raspberry Pi  (~/Documents)
 камера -> tracker/ (Hailo YOLO + ReID) -> fusion/ (лидар в рамке, calib.json)
        -> PersonFix(bearing, range)
                    |
 scripts/follow.py  |  поток управления, ровно раз в Ts = 0.09 с:
                    v
   control/bridge.py: d, phi + точки лидара в СК робота (человек вырезан)
   control/nucleo.py: velocity() <- E|vx|vy|w  (новое)            ^
   control/dwa_py.py -> libdwa4.so : dwa4_step(d, phi, conf, obs, u_prev = скорость с энкодеров)
   control/nucleo.py: send(vx, vy, w) -> M3|мм/с|мм/с|мрад/с ------+
   control/stream.py: видео :8080 (рамка, d, phi, стрелка, дуга)  |
                                                                   | UART 115200, /dev/ttyUSB1
                       STM32G474 (Telechka_Nucleo)                 v
   M3 -> MecanumIK -> 4 x PI-регулятор (Motor) -> ШИМ
   Холл x4 -> WheelOdometry (новое): |w| + знак -> прямая кинематика -> E|... каждые 20 мс
```

## Что меняется

| Где | Файл | Что |
|---|---|---|
| STM | `Core/Src/WheelOdometry/*` (новая папка) | скорость корпуса по Холлам, строка `E\|...`, команда `ENC\|ms` |
| STM | `MecanumIK.hpp` | +3 геттера `r, lx, ly` |
| STM | `main.cpp` | 4 вставки: include, объект `odom`, `ENC` в разборе команд, `odom.poll()` |
| Pi | `control/dwa4.h`, `control/dwa_v4_static_stop.c` | новый DWA на C + OpenMP, собирается в `libdwa4.so` |
| Pi | `control/dwa_py.py` | обёртка под `libdwa4.so`, `step(..., u_prev=...)` |
| Pi | `control/nucleo.py` | приём `E\|...`, `velocity()`, `ENC\|20` при старте и `ENC\|0` при выходе |
| Pi | `scripts/follow.py` | одна строка: `u_prev = NUCLEO.velocity()` в `dwa.step` |
| Pi | `scripts/enc_check.py` | проверка энкодеров на подставке |

Подробно про прошивку: [`stm/README_STM.md`](stm/README_STM.md).

## Порядок

1. **Прошивка.** Парни вставляют блок из `stm/` по `stm/README_STM.md`, прошивают и
   проверяют в miniterm: `ENC|200`, `M3|300|0|0` → идут строки `E|~300|0|0|15|...`.
2. **Распа.** Скачать `pi/install_dwa4_enc.txt` и выполнить:
   ```bash
   bash ~/Downloads/install_dwa4_enc.txt
   ```
   Он делает копии `*.bak_v3`, пишет новые файлы, переносит в новый `nucleo.py` твои
   `PORT`, `V_MAX`, `W_MAX`, `LOG_*`, `SIGN_*`, правит одну строку в `follow.py`,
   собирает `libdwa4.so` и делает пробный шаг DWA. В конце `BUILD_OK` и `INSTALL_OK`.
   Весь файл на ASCII, вставка через Remmina его не портит.
3. **Проверка энкодеров** (робот на подставке):
   ```bash
   cd ~/Documents && python3 -m scripts.enc_check
   ```
   Знаки `measured` должны совпадать с `command`, при `mask 15` отношение около 1.
4. **Запуск** как раньше:
   ```bash
   cd ~/Documents && python3 lidar_reset.py && OMP_NUM_THREADS=2 python3 -m scripts.follow --drive
   ```
   В строке `[CTRL]` появилось `u0=enc` (скорость с энкодеров) или `u0=cmd`
   (энкодеров нет, взята прошлая команда — старая прошивка или запуск без `--drive`).
   Режим `HOLD` = робот подъехал на d0 = 0.6 м и тормозит.
5. **Откат:**
   ```bash
   cd ~/Documents/control && cp dwa_py.py.bak_v3 dwa_py.py && cp nucleo.py.bak_v3 nucleo.py \
     && cp ../scripts/follow.py.bak_v3 ../scripts/follow.py
   ```

Необязательные ключи в `control/robot.json` (без них работают значения по умолчанию):
```json
  "u_prev_from_encoders": true,
  "enc_max_age_s": 0.20
```
`false` вернёт старое поведение (`u_prev` = прошлая команда) без отката файлов.

## Новый DWA на C

`pi/control/dwa_v4_static_stop.c` — построчный порт `.m`: те же константы, тот же
порядок операций, тот же выбор при равной стоимости (первый по порядку циклов
`i, j, k`). Persistent-переменные — в структуре `dwa4_state_t`.

Параллельность — как в v2/v3: кандидаты `(vx, vy, w)` раздаются потокам OpenMP
(`schedule(dynamic, 4)`), каждый поток ищет своего лучшего, потом лучшие
сравниваются с правилом «при равенстве меньший номер». Поэтому команда не зависит
от числа потоков. Сборка с `-DDWA4_PREFILTER=1` включает отсев точек лидара,
до которых робот за горизонт не доедет (как фильтр v3): команда та же, меньше работы.
По умолчанию отсев выключен, как в `v2_nofilter`, который у тебя стоял.

Отличия от старого (v2/v3):
- нет оценщика скорости человека (`vx_t_est`, `vy_t_est`), цель берётся прямо из
  измерения. Раскачка из-за задержки камеры через этот оценщик (то, что мы
  разбирали в прошлый раз) здесь уйти должна;
- `HOLD`: в 2.5 см / 0.035 рад от цели робот плавно тормозит до нуля и стоит,
  выходит из `HOLD` при 6 см / 0.08 рад;
- боковое движение запрещено (`vy_cap = 0.03`);
- другие пределы: `ax = ay = 1.719`, `aw = 4.04`, колесо 25.51 рад/с и 22.92 рад/с²,
  `L = 0.425`, `R_robot_eq = 0.30`, `d0 = 0.60` (в `dwa4.h`).

## Почему `u_prev` с энкодеров

Динамическое окно строится вокруг `u_prev`: `[u_prev − a·Ts, u_prev + a·Ts]`, туда же
смотрят проверка ускорения колёс, штраф за рывок и торможение в `HOLD`. Если
`u_prev` — прошлая команда, алгоритм считает, что робот уже едет так, как ему
сказали. Моторы разгоняются с запаздыванием, и окно уезжает вперёд реальной
скорости. Со скоростью с энкодеров окно стоит там, где робот на самом деле.

## Что проверено

- C-порт против исходного `.m` в Octave (с `linspace` как в MATLAB), случайные шаги и
  замкнутые прогоны с `HOLD`/`SEARCH`: 403 шага (TRACK, ALIGN, SPIN, SEARCH, HOLD),
  расхождение **0**, бит в бит (`test/compare_octave.py`).
- Последовательная сборка, OpenMP и OpenMP с отсевом дают одинаковые команды (разница 0).
- Время шага на ПК (x86, 360 точек лидара): 1.1 мс в один поток, 0.25 мс на 4 потоках,
  0.3 мс на 2, с отсевом 0.05 мс (`test/bench.py`). На распе будет в несколько раз
  медленнее, но до 90 мс далеко.
- `WheelOdometry` собран на ПК с заглушками HAL: прямая кинематика возвращает
  ту скорость, из которой посчитаны колёса; разбор `ENC|...`; подстановка уставки,
  когда Холл молчит (`test/stm_host`).
- `nucleo.py` против фальшивой STM на виртуальном порту: `PING`, `ENC|20`, приём `E`,
  знак `SIGN_*`, `ENC|0` при выходе (`test/fake_stm_nucleo.py`).
- Установщик прогнан на копии твоих `follow.py` и `nucleo.py` (`BUILD_OK`, `INSTALL_OK`).

**Не проверено:** на самом роботе и на настоящей STM. Прошивку я не компилировал под
ARM: в архиве старая версия, а у парней сейчас другая.

## Что ещё в стеке стоит поправить

- **Геометрия в прошивке** (`r = 0.17`, `lx + ly = 0.45`) не совпадает с DWA (`0.075`,
  `0.425`). Для `E` важно, чтобы в прошивке стояли **реальные** размеры.
- **Холл 4 импульса на оборот**: медленные колёса не видны, для них в `E` идёт уставка
  (`mask < 15`). Для честных малых скоростей нужно больше магнитов или энкодер на валу.
- `W_MAX` в `nucleo.py` (1.5 или 1.8) режет команду. Алгоритм может просить до 1.8 рад/с
  (ALIGN/SPIN). С `u_prev` с энкодеров это уже не ломает окно, но поворот будет ограничен.
- Баги прошивки, которые обходятся с распы: `smooth_stop()` вызывает сама себя
  (поэтому ноль шлётся как `M4|0|0|0|0`), `STOP` не выключает режим M3, нет watchdog
  (если распа упадёт, робот поедет дальше с последней командой).
- `fusion/lidar_source.py`: искать порт лидара по `*CP2102*`, а не первый попавшийся.
- `control/stream.py`: `SHOW = False`, окно в Remmina тормозит главный цикл.

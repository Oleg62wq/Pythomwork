# STM (Telechka_Nucleo): блок скоростей с энкодеров

Прошивка сама считает реальную скорость корпуса `vx, vy, w` по четырём датчикам Холла
и шлёт её на распу. Распа подставляет эту скорость в DWA как `u_prev`, вместо
предыдущей команды алгоритма.

```
Холл x4 -> |w_i| (рад/с) -> знак = направление, в котором крутим мотор
        -> прямая кинематика (обратная к MecanumIK::calculate, те же r, lx, ly)
        -> "E|vx|vy|w|mask|t\r\n" каждые 20 мс -> распа -> DWA(u_prev)
```

## Протокол (добавлено к M3/M4/PING/STOP)

| Команда (Pi -> STM) | Ответ | Что делает |
|---|---|---|
| `ENC\|20` | `ENC: 20` | слать `E\|...` каждые 20 мс (допустимо 10..1000) |
| `ENC\|0` | `ENC: 0` | выключить (так после включения платы) |

Строка от STM: `E|vx|vy|w|mask|t`
- `vx`, `vy` — мм/с, `w` — мрад/с; оси и единицы те же, что у `M3`;
- `mask` — биты 0..3 = колёса FL, FR, RL, RR. 1 = скорость колеса измерена Холлом,
  0 = Холл молчит дольше 250 мс (колесо слишком медленное), вместо замера взята
  уставка колеса (в режиме M3) или 0 (после M4/STOP);
- `t` — `HAL_GetTick()`, мс.

Старая распа без новой программы просто не шлёт `ENC|...`, и прошивка ведёт себя как раньше.

## Что поменять в проекте

Мотор, датчик Холла и парсер **не трогаются**. Новый код лежит в отдельной папке,
в `main.cpp` добавляется 4 вставки, в `MecanumIK.hpp` три строки.

### 1. Новая папка
Скопировать `Core/Src/WheelOdometry/` (`WheelOdometry.hpp`, `WheelOdometry.cpp`) в
`Core/Src/` проекта.

Если собираете через `make`, добавьте файл в список исходников C++ в `Makefile`
(рядом с `Core/Src/Motor/Motor.cpp`):
```make
Core/Src/WheelOdometry/WheelOdometry.cpp \
```
В STM32CubeIDE папка из `Core/Src` подхватывается сама.

### 2. `Core/Src/MecanumIK/MecanumIK.hpp` — три геттера в `public:`
```cpp
    float get_r()  const { return r; }
    float get_lx() const { return lx; }
    float get_ly() const { return ly; }
```
Прямая кинематика берёт `r`, `lx`, `ly` отсюда, поэтому она всегда совпадает с той
обратной, которая крутит колёса.

### 3. `Core/Src/main.cpp`

**3.1** К остальным `#include` в начале:
```cpp
#include "WheelOdometry/WheelOdometry.hpp"
```

**3.2** Сразу после `MecanumIK ik;`:
```cpp
WheelOdometry odom(&motor1, &motor2, &motor3, &motor4,
                   &hall1, &hall2, &hall3, &hall4, &ik);
```
Порядок FL, FR, RL, RR, как в `ik.wheel_speeds`.

**3.3** В обработке команды, сразу после строки
`std::string_view cmd(local_buffer, len);` и **до** `CommandParser::parse(cmd)`:
```cpp
      if (odom.handle_command(cmd)) {      // ENC|<ms>
          flag_get_message = false;
          continue;
      }
```

**3.4** В самом конце тела `while (1)` (после блока `Rot/min`):
```cpp
      odom.poll(flag_m3_mode);

      // если приём UART вдруг не перезапустился в прерывании - перезапускаем
      if (huart1.RxState == HAL_UART_STATE_READY)
          HAL_UART_Receive_IT(&huart1, &rx_char, 1);
```
Вторая часть — страховка. STM теперь отвечает чаще (50 строк в секунду), и если
`HAL_UART_Receive_IT` внутри прерывания вернёт `HAL_BUSY`, приём команд встанет
навсегда. Эта проверка его поднимает.

### 4. `HallSensor::is_stalled(uint32_t)` должен быть `public`
В архиве он есть (`HallSensor.cpp`, строка 113). Если в `.hpp` он в `private`,
перенесите объявление в `public:`.

## Проверка на подставке (колёса в воздухе)

```bash
python3 -m serial.tools.miniterm /dev/ttyUSB1 115200 --eol LF
```
```
ENC|200          -> ENC: 200, потом раз в 0.2 с E|0|0|0|0|...
M3|300|0|0       -> E|~300|0|0|15|...   (вперёд, mask 15 = все 4 колеса видны)
M3|0|0|800       -> E|0|0|~800|15|...   (поворот влево)
M4|0|0|0|0
ENC|0
```
Выход: `Ctrl+]`. Или сразу на распе: `cd ~/Documents && python3 -m scripts.enc_check`.

Если `vx` из `E` получается с другим знаком, чем в `M3`, значит у какого-то мотора
перепутаны провода/пины, и сначала надо чинить это (иначе и `M3` едет не туда).

## Геометрия: проверить до запуска

`E` считается через `r`, `lx`, `ly` из `MecanumIK`. Если они не равны реальным
размерам робота, `E` будет показывать то, что «думает» прошивка, а не реальную
скорость: при идеальном ПИДе `E` просто вернёт команду `M3`.

| | `MecanumIK` (в архиве) | DWA (`.m`) |
|---|---|---|
| радиус колеса `r` | 0.17 м (в README прошивки 0.15) | 0.075 м |
| `lx + ly` | 0.45 м | `L` = 0.425 м |

Если колесо диаметром 150 мм, в прошивке должно стоять `r = 0.075`. Сверьте с тем, что
сейчас прошито у парней, и с рулеткой. Проверка: `M3|200|0|0` на полу 5 секунд —
робот должен проехать 1 м.

## Ограничения датчиков (важно понимать)

- **4 импульса на оборот колеса.** При 1–2 рад/с на колесе Холл даёт импульс раз в
  0.8–1.5 с, и скорость не видна. Для таких колёс в `E` уходит уставка, а в `mask`
  бит = 0. Порог `STALL_MS = 250` в `WheelOdometry.hpp`: колесо считается видимым
  примерно от 6 рад/с (около 0.45 м/с корпуса при r = 0.075). Медленнее робот
  фактически получает обратно свою же команду. Чтобы мерить малые скорости,
  нужно больше магнитов на колесо или энкодер на валу мотора.
- **Нет направления.** Знак берётся из уставки мотора. В момент смены направления
  колесо ещё крутится в старую сторону, а знак уже новый: одна–две строки `E` будут
  с ошибкой по знаку.
- **Переполнение TIM4** в периодном методе (описано в README прошивки): на малых
  скоростях Холл занижает период. Это остаётся как было.
- `E` строится по последнему периоду между импульсами, на 4 импульсах на оборот
  обновление при 10 рад/с — раз в ~0.16 с.
